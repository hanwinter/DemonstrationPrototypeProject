基于当前已经修改完成的“自费订单详情”弹框继续进行一轮小幅 UI 优化。

**当前整体设计方向已经正确，本次不要重新设计页面，不修改字段、不修改业务逻辑、不调整表格结构，只处理以下 4 个 UI 问题。**

### 1. 进一步降低分组标题视觉权重

当前以下分组标题字号仍然偏大：

* 订单信息
* 自费项目明细
* 支付摘要
* 操作记录

统一调整：

```css
font-size: 16px;
font-weight: 500;
color: #475569;
```

要求：

* 不使用粗体
* 不增加背景色
* 不增加左侧色条
* 不增加图标
* 保持现在简洁的纯文本标题形式

分组标题只承担信息分区作用，不要成为页面主要视觉焦点。

---

### 2. 压缩页面纵向留白

当前各信息区域之间的上下间距偏大，导致页面整体过于松散、滚动距离过长。

在保持页面呼吸感的前提下，将整体纵向间距压缩约 **15%～20%**。

重点调整：

* 分组标题与上一分组之间的距离
* 分组标题与字段内容之间的距离
* 字段区域与分割线之间的距离
* 表格与“支付摘要”之间的距离
* “支付摘要”与“操作记录”之间的距离

建议参考：

```text
分组顶部间距：约 24px
标题 → 内容：约 14～16px
内容 → 分割线：约 18～20px
分割线 → 下一分组标题：约 22～24px
```

不要压缩得像密集表单，目标是形成**紧凑但有呼吸感的后台详情页**。

---

### 3. 修复“支付流水号”换行问题

当前页面出现：

```text
支付流水
    号：
```

这是错误的排版效果。

必须调整为完整单行：

```text
支付流水号： PAY202604180001
```

同时检查“订单信息”和“支付摘要”两个两列信息区域。

所有字段 Label：

```css
white-space: nowrap;
```

禁止字段名称自动换行。

两列继续保持统一的 Label-Value Grid：

```text
订单编号： ZF202604180001       下单时间：   2026-04-12 09:20
订单状态： 正常                 订单金额：   ¥85
```

支付摘要：

```text
支付状态： 已支付               支付方式：   微信支付
支付时间： 2026-04-12 09:22     支付流水号： PAY202604180001
```

每一列内部：

* Label 固定合理宽度
* Label 右对齐
* Value 左对齐
* Label 与 Value 间距统一
* 两列起始位置保持一致
* 不要因为某个 Label 较长导致 Value 错位
* 不允许 Label 被拆成两行

---

### 4. 删除底部“关闭”按钮及 Footer

当前弹框属于纯查看型详情页面，右上角已经存在“×”关闭操作，因此底部“关闭”按钮属于重复操作。

调整：

* 删除右下角“关闭”按钮
* 删除其所在 Footer 区域
* 仅保留右上角“×”作为关闭入口
* 内容滚动区域自然延伸到底部
* 最后一条“操作记录”之后保留约 `24px` 的底部留白即可

删除 Footer 后注意重新计算弹框内容区域高度，避免底部出现不必要的大块空白。

---

### 保持不变的内容

以下部分当前效果已经符合要求，**不要重新设计**：

* “自费订单详情”顶部主标题
* 右上角关闭 ×
* 订单金额 `¥85` 的绿色强调
* “已支付”轻量绿色状态 Tag
* 自费项目明细表格当前整体风格
* 操作记录当前轻量 Log List 风格
* 当前弹框宽度
* 当前字段及 Mock 数据
* 当前整体白色、轻量 SaaS 后台风格

本轮修改原则：

**只做减法和细节修正，不重新设计页面。最终形成“弱分组标题 + 清晰字段层级 + 紧凑留白 + 关键业务信息强调”的现代 SaaS 订单详情弹框，并将该视觉样式作为后续订单类详情页面可复用的 UI 范式。**
