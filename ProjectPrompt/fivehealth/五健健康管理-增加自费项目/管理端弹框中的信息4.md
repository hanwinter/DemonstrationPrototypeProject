请基于当前“自费订单详情”弹框进行 UI 结构优化。

当前页面虽然已经降低了字体权重，但仍存在明显的**信息分组过多、标题过多、横向分割线过多、传统表单感较强、视觉焦点不明确**的问题。

本次不要继续在现有 5 个分组基础上简单调整字号和间距，而是重新组织页面信息层级。

**只调整 UI 布局和信息组织方式，不修改任何业务字段、业务数据和业务逻辑。**

## 一、整体结构调整

当前页面存在：

* 基本信息
* 订单信息
* 自费项目明细
* 支付摘要
* 操作记录

5 个独立分组。

调整后取消：

* “基本信息”标题
* “订单信息”标题
* “支付摘要”标题

将以上三个区域的信息合并为顶部统一的：

**订单摘要区**

但注意：

**“订单摘要”本身也不要显示标题。**

最终整个弹框正文只保留两个分组标题：

1. 自费项目明细
2. 操作记录

最终页面结构：

```text
自费订单详情                                  ×


[订单摘要区]


自费项目明细
[项目明细表格]


操作记录
[操作日志]
```

减少页面切割感。

## 二、顶部改为订单摘要式布局

顶部不要继续使用传统的：

```text
学生姓名：林一凡
学校：实验小学
班级：三年级2班
……
```

这种纯表单式排列。

改为“身份摘要 + 核心订单状态 + 次级订单属性”的信息组织方式。

### 左上：学生身份摘要

将学生作为订单主体首先展示。

建议：

```text
林一凡
三年级2班 · 实验小学
家长：林女士    13800010001
```

其中：

### “林一凡”

作为摘要区主要信息：

* 字号约 `18px`
* `font-weight: 600`
* 深色正文
* 不需要“学生姓名：”Label

### “三年级2班 · 实验小学”

作为辅助身份信息：

* `14px`
* 正常字重
* 中性灰
* 班级和学校使用 `·` 分隔
* 不需要“班级：”“学校：”Label

### 家长信息

展示：

```text
家长：林女士    13800010001
```

使用普通正文，不需要强调。

不要增加卡片、头像、图标或背景色。

## 三、右上突出订单核心状态

订单摘要区域右侧展示：

```text
已支付
¥85
```

形成整个弹框最明确的订单视觉焦点。

建议：

### 已支付

继续使用当前轻量绿色 Tag：

* 浅绿色背景
* 深绿色文字
* 小尺寸
* 不使用高饱和度颜色

### ¥85

作为核心订单金额：

* 字号约 `22px`
* `font-weight: 600`
* 使用当前主题绿色
* 金额比状态更突出

状态和金额可以横向展示，例如：

```text
已支付    ¥85
```

也可以上下轻量排列，但不要设计成独立卡片。

## 四、订单属性统一收纳到摘要区下方

学生身份摘要下方统一展示剩余订单属性。

保留：

* 订单编号：ZF202604180001
* 订单状态：正常

* 支付方式：微信支付
* 支付时间：2026-04-12 09:22

建议采用紧凑的两列 Description Grid：

```text
订单编号    ZF202604180001        下单时间    2026-04-12 09:20

```

要求：

* Label 使用灰色
* Value 使用深色
* 普通 Value 不加粗
* Label 不需要冒号
* Label 与 Value 保持固定间距
* Label 禁止换行
* 每列内部对齐
* 两列之间保持合理距离
* 行高紧凑但不能拥挤

不要给这一部分增加“订单信息”“支付摘要”等标题。

* 灰色背景块
* 描边
* 阴影
* 渐变
* 左侧色条
* 装饰图标

通过：

## 八、大幅减少横向分割线

当前页面分割线数量过多，本次需要减少。

原则：

只在三个主要区域之间进行分隔：

```text
订单摘要
────────────

自费项目明细
────────────

操作记录
```

不要在订单摘要内部因为“基本信息”“订单信息”“支付信息”继续增加横线。

目标是让页面从多个碎片化区域变成三个连续的信息层级。

---

## 九、控制整体纵向高度

当前弹框内容并不多，不应该产生明显冗长的滚动距离。

调整后：

* 减少标题数量
* 减少分组上下留白
* 合并基本信息、订单信息、支付信息
* 压缩无意义空白
* 保持适当呼吸感

目标是在当前弹框尺寸下尽可能完整展示主要订单信息。

不要为了填满弹框而人为增加留白。

## 十、最终视觉目标

本次优化的重点不是“把标题变小”，而是**重新建立订单详情的信息层级**。

最终用户打开弹框后，视觉阅读顺序应该非常明确：

```text

   林一凡 · 三年级2班 · 实验小学

② 当前状态和金额
   已支付  ¥85

④ 买了什么
   自费项目明细

⑤ 订单发生过什么
   操作记录
```

整体采用：

**订单摘要 + 明细表格 + 操作日志**

三层结构。

不要再恢复“基本信息 / 订单信息 / 支付摘要”三个独立模块。

不要新增装饰性 UI。
