基于当前“自费订单详情”弹框继续进行局部 UI 优化。

**当前顶部订单摘要区域已经符合要求，不要修改。**

本次只调整以下两个区域：

1. 自费项目明细
2. 操作记录

目标是解决目前两个区域视觉语言过于相似、都呈现明显“表格感”，导致页面下半部分层级混乱的问题。

整体设计原则：

**自费项目明细 = 轻量结构化表格**
**操作记录 = 轻量纵向时间线**

两种信息使用不同的视觉表达方式。

---

## 一、自费项目明细改为轻量表格

保留：

* “自费项目明细”标题
* 项目名称
* 项目分类
* 单价
* 数量
* 小计
* 当前所有 Mock 数据

仍然使用表格结构，因为实际订单可能包含多个自费项目。

但是降低传统后台表格的视觉重量。

### 1. 表头

取消或弱化当前明显的表头背景色。

建议直接使用白色背景：

```css
background: transparent;
```

表头文字：

```css
font-size: 14px;
font-weight: 400;
color: #64748B;
```

不要使用粗体表头。

### 2. 数据行

数据行：

```css
font-size: 15px;
font-weight: 400;
color: #1F2937;
```

行高控制在约：

```css
height: 48px;
```

不要让单条数据占据过高空间。

### 3. 对齐规则

保持：

* 项目名称：左对齐
* 项目分类：左对齐
* 单价：右对齐
* 数量：居中
* 小计：右对齐

金额正常显示，不需要加粗。

### 4. 分割线

不要使用明显的完整表格边框。

仅保留非常浅的横向行分割线：

```css
border-color: #E5E7EB;
```

不要：

* 外边框
* 纵向分割线
* 阴影
* 圆角卡片
* 灰色大面积背景

让这个区域更接近“结构化数据列表”，而不是传统 DataTable。

---

## 二、压缩“自费项目明细”区域高度

当前标题、表头、数据行之间的纵向距离偏大。

适当压缩：

```text
自费项目明细
↓ 12~16px
表头
↓
数据行
```

标题建议：

```css
font-size: 16px;
font-weight: 500;
color: #475569;
```

标题不要再承担过强视觉权重。

---

# 三、操作记录不要继续使用三列表格

当前操作记录类似：

```text
2026-04-12 10:12    创建自费订单    订单已生成
2026-04-12 10:12    等待支付确认    支付处理中
```

这种排版实际上仍然是一个没有表头的三列表格。

本次将“操作记录”彻底调整为：

**轻量纵向时间线 / Event Log Timeline**

不要继续使用三列 Grid。

---

# 四、操作记录推荐结构

调整为：

```text
●  创建自费订单
   2026-04-12 10:12 · 订单已生成

│

●  等待支付确认
   2026-04-12 10:12 · 支付处理中
```

每一条操作记录由两层信息组成。

### 第一层

操作名称：

```text
创建自费订单
```

或：

```text
等待支付确认
```

样式：

```css
font-size: 15px;
font-weight: 500;
color: #1F2937;
```

作为该事件的主要信息。

### 第二层

将时间和结果合并：

```text
2026-04-12 10:12 · 订单已生成
```

例如：

```text
2026-04-12 10:12 · 支付处理中
```

样式：

```css
font-size: 13px;
font-weight: 400;
color: #94A3B8;
```

时间与结果之间使用：

```text
·
```

进行自然分隔。

不要继续把时间、操作名称、结果做成三列。

---

# 五、时间线样式保持极简

每条记录左侧增加一个小圆点。

建议：

```css
width: 6px;
height: 6px;
border-radius: 50%;
```

使用低饱和度主题色或中性灰蓝色。

相邻事件之间可以增加一条非常浅的纵向连接线。

连接线：

```css
width: 1px;
```

颜色使用：

```css
#E5E7EB
```

注意：

**时间线只能作为轻量的信息引导，不要做成传统 Ant Design Timeline 那种视觉较重的组件。**

不要：

* 大圆点
* 彩色圆点
* 图标
* 大面积状态颜色
* 卡片
* 背景块
* 横向分割线

---

# 六、删除操作记录中的横向分割线

当前每条操作记录之间存在横向分割线。

全部删除。

改为通过：

**小圆点 + 极浅纵线 + 垂直间距**

表达事件之间的关系。

每条事件之间保持约：

```css
16px ~ 20px
```

的纵向间距。

---

继续保留：

```text
操作记录
```

标题样式与“自费项目明细”完全一致：


两个区域标题必须属于同一视觉层级。

# 八、两个区域之间的关系

最终页面下半部分应该形成明显不同的两种信息表达：

```text
自费项目明细

项目名称        项目分类        单价    数量    小计
骨龄检测        影像检查         ¥80      1      ¥80


────────────────────────────────


操作记录

●  创建自费订单
│  2026-04-12 10:12 · 订单已生成
│
●  等待支付确认
   2026-04-12 10:12 · 支付处理中
```

注意：

上面的示意仅表达信息结构，不要求机械复制字符线条。

核心原则：

**项目明细横向阅读，操作记录纵向阅读。**

避免两个区域都表现成表格。

# 最终目标

本轮不要再对整个弹框进行大范围修改。

只解决下半部分的视觉混乱：

**自费项目明细采用“轻表格”，用于表达结构化项目数据；操作记录采用“轻时间线”，用于表达订单事件过程。**

通过两种不同的信息展示范式，让用户能够快速区分：

**“买了什么”与“订单发生了什么”。**
