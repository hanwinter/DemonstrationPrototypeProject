当前页面整体结构已经基本确定，本次**不要调整“自费项目明细”“操作记录”等下方区域，不修改业务逻辑、不修改 Mock 数据，只优化顶部学生身份信息以及订单费用/状态信息的表达方式。**

本次重点解决两个问题：

2. 当前右上角仅展示“已退款 + ¥30”，金额业务含义不够明确。作为订单详情页，应明确告诉用户这是订单金额、实付金额还是退款金额。

## 一、学生身份摘要压缩为两行

当前：

```text
赵明轩
四年级3班 · 实验小学
家长：赵先生    13800010003
```

调整为：

```text
赵明轩    四年级3班 · 实验小学
家长：赵先生    13800010003
```

即：

**学生姓名 + 班级 + 学校放在第一行；家长姓名 + 联系电话放在第二行。**

### 第一行

参考：

```text
赵明轩    四年级3班 · 实验小学
```

其中学生姓名是主要身份信息：

```css
font-size: 18px;
font-weight: 600;
color: #1F2937;
```

班级、学校作为辅助身份信息：

```css
font-size: 14px;
font-weight: 400;
color: #64748B;
```

姓名与班级之间保持约：

```css
gap: 12px ~ 16px;
```

班级和学校之间继续使用：

```text
四年级3班 · 实验小学
```

不要恢复：

```text
学生姓名：
班级：
学校：
```

等传统字段 Label。

不要把班级、学校做成 Tag。

---

## 二、家长信息作为第二行辅助信息

第二行：

```text
家长：赵先生    13800010003
```

建议：

```css
font-size: 14px;
font-weight: 400;
color: #475569;
```

“家长：赵先生”和联系电话之间保持自然间距，例如：

```css
gap: 20px ~ 24px;
```

不需要增加：

```text
联系电话：
```

保持摘要式表达。

# 三、右上角从“状态 + 金额”升级为“费用摘要”

当前右上角：

```text
[已退款]   ¥30
```

业务含义不够直接。

用户无法快速判断 ¥30 表示：

* 订单金额
* 实付金额
* 退款金额

因此本次将右上角统一调整为：

**费用摘要区。**

# 四、主金额永远明确显示“订单金额”

无论订单处于：

* 待支付
* 已支付
* 退款中
* 已退款
* 部分退款
* 已关闭
* 支付失败

右上角主金额的业务定义始终保持一致：

```text
订单金额
¥30
```

不要根据状态把主金额名称切换成“实付金额”或“退款金额”。

这样保证用户在任何订单状态下都能明确知道：

**这个订单原始应付多少钱。**

# 五、推荐的费用摘要布局

推荐右上角采用：

```text
                         订单金额
                         ¥30   [已退款]
                         实付 ¥30 · 退款 ¥30
```

整体右对齐。

其中第一层：

```text
订单金额
```

作为金额说明：

```css
font-size: 13px;
font-weight: 400;
color: #64748B;
```

第二层：

```text
¥30   [已退款]
```

其中订单金额：

```css

font-weight: 600;

```

状态 Tag 放在金额右侧：

```css

justify-content: flex-end;

```

第三层：

```text
实付 ¥30 · 退款 ¥30
```

作为资金状态辅助说明：

```css
font-size: 13px;
font-weight: 400;
color: #64748B;
```

不要加粗。

# 六、不同订单状态的费用表达规则

费用摘要结构保持固定，只根据业务状态改变辅助信息和状态 Tag。

### 1. 待支付

```text
订单金额
¥80   [待支付]
待支付 ¥80
```

### 2. 已支付

```text
订单金额
¥85   [已支付]
实付 ¥85
```

### 3. 退款中

```text
订单金额
¥30   [退款中]
实付 ¥30 · 退款 ¥30
```

### 4. 已退款

当前页面使用：

```text
订单金额
¥30   [已退款]
实付 ¥30 · 退款 ¥30
```

### 5. 部分退款

例如：

```text
订单金额
¥100   [部分退款]
实付 ¥100 · 已退款 ¥30
```

这里不要只显示 ¥30，否则用户容易误认为订单金额是 ¥30。

### 6. 已关闭且未支付

```text
订单金额
¥30   [已关闭]
未支付
```

### 7. 支付失败

```text
订单金额
¥30   [支付失败]
支付未完成
```

# 七、状态 Tag 建立统一语义色规范

不同订单状态不要全部使用绿色。

### 待支付

使用轻量橙色：

* 浅橙背景
* 深橙文字

表达“待处理”。

### 已支付

使用绿色：

* 浅绿色背景
* 深绿色文字

表达支付完成。

### 退款中

使用蓝色：

* 浅蓝背景
* 深蓝文字

表达流程处理中。

### 已退款

使用灰蓝或青灰色：

* 浅灰蓝/浅青背景
* 深灰蓝/深青文字

不要继续与“已支付”使用完全相同的绿色。

### 部分退款

可以使用轻量蓝色或青色，与“已退款”保持同一退款语义体系。

### 已关闭

使用中性灰：

* 浅灰背景
* 深灰文字

降低视觉权重。

### 支付失败

使用轻量红色：

* 浅红背景
* 深红文字

红色只用于异常状态。

所有状态 Tag：

* 尺寸保持一致
* padding 保持一致
* 圆角保持一致
* 字号保持一致
* 不要使用高饱和度背景色
* 状态切换时不要导致布局跳动

---

# 八、金额颜色不要跟随状态 Tag 频繁变化

金额本身是业务数据，不是状态。

因此不要：

```text
待支付 → 金额橙色
已支付 → 金额绿色
退款 → 金额蓝色
失败 → 金额红色
```

这种设计会导致页面颜色过多。

统一规则：

### 正常订单

订单金额使用：

```css
color: #1F2937;
```

或者沿用系统当前核心金额的主题深绿色，但必须统一。

### 已关闭等失效订单

可以适当降低金额权重：

```css
color: #64748B;
```

### 支付失败

金额也不要使用红色。

红色仅用于“支付失败”状态 Tag。

# 九、费用摘要整体右对齐

整个费用摘要区固定在顶部摘要区域右侧。

要求：

```css
text-align: right;
```

金额 + 状态使用：

```css
display: flex;
align-items: center;
justify-content: flex-end;
gap: 10px ~ 12px;
```

保证：

* “订单金额”右对齐
* 金额与状态 Tag 水平排列
* Tag 与金额视觉中线对齐
* 辅助费用信息右对齐
* 整个费用摘要区域的位置固定

切换不同订单状态时，不能因为文字长度变化造成整体位置明显跳动。

订单编号    ZF202604180003       下单时间    2026-04-13 15:30
支付方式    微信支付              支付时间    2026-04-13 15:32
支付流水号  PAY202604180003      订单状态    已关闭

注意：

右上角的“已退款”属于**支付/退款状态**。

下面订单属性中的“订单状态：已关闭”属于**订单生命周期状态**。

两者是不同业务概念，不要因为文字看起来相近而合并。
