继续优化“到岗当日服务记录”上级页面。

本次按照真实业务流程调整页面结构和交互，不修改已有订单数据。

1. 订单信息卡片优化

订单信息展示方式与“到岗当日服务记录”二级页保持一致。

改为字段名和值同行，短字段一行两个，例如：

宝妈：王女士        当前服务员：张洪霞

订单编号：DD202608060001

服务周期：2026-08-01 至 2026-08-14

减少当前上下堆叠式排版。


2. 删除“新增”按钮

删除订单信息卡片右上角“新增”。

到岗当日服务记录不允许人工新增。

业务规则改为：

- 合同中的第一个服务员确认到岗后，系统自动生成一条“到岗当日服务记录”，状态为“待填写”。
- 订单发生服务员更换时，新服务员确认到岗后，系统自动生成属于该服务员的一条“到岗当日服务记录”。
- 每个实际到岗服务员必须且只能对应一条到岗当日服务记录。
- 历史服务员记录必须保留，不覆盖、不删除。


3. 页面及模块名称修改

将所有：

“首日服务档案”

统一改为：

“到岗当日服务记录”

包括：
- 页面标题
- 列表模块标题
- 二级页面标题
- 相关提示文字


4. 列表交互重新设计

当前列表中的：

[状态标签] [查看/继续填写按钮]

改为移动端列表交互方式。

每条记录展示：

张洪霞
到岗日期：2026-08-01            [已发送]   >

李小红
到岗日期：2026-08-05            [待填写]   >

要求：

- 保留状态标签；
- 删除“查看”“继续填写”等操作按钮；
- 右侧统一使用箭头；
- 整个列表项可点击；
- 点击进入对应的到岗当日服务记录二级页面。


5. 二级页面根据记录状态自动决定模式

点击列表记录后，不在上级页面区分“查看/填写/修改”。

二级页面根据状态自动进入对应模式：

待填写：
→ 编辑模式
→ 支持保存、发送到公司

已发送/已提交：
→ 查看模式
→ 不可直接编辑
→ 支持申请修改

修改申请中：
→ 查看模式
→ 展示审核中状态

修改申请通过：
→ 编辑模式
→ 修改完成后重新发送到公司

修改申请驳回：
→ 查看模式
→ 展示驳回原因


6. 列表状态建议统一为：

- 待填写
- 草稿
- 已发送
- 修改申请中
- 可修改
- 修改申请驳回

状态使用轻量标签展示。


7. 保留完整历史记录

订单更换服务员后：

例如：

张洪霞
到岗日期：2026-08-01
[已发送] >

李小红
到岗日期：2026-08-05
[待填写] >

两条记录同时保留。

不要因为更换当前服务员而覆盖前一位服务员的到岗记录。


8. 业务原则

“到岗当日服务记录”属于服务人员履约自动触发的业务记录，不是人工创建的普通档案。

整体流程：

服务员确认到岗
→ 系统自动生成待填写记录
→ 服务员填写
→ 保存草稿
→ 发送到公司
→ 记录锁定
→ 如需修改则申请修改
→ 公司审核
→ 修改
→ 重新发送
→ 全程留痕

目标：
把当前页面从“人工新增档案列表”调整为“按服务人员履约自动生成的到岗记录管理页面”。
