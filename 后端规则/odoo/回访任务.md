**共同基础**
页面统计都应基于同一个查询上下文：

- 统计日期：`viewDate`
- 顾问：全部 / 指定顾问
- 回访类型：全部 / 产后回访 / 服务回访
- 状态：全部 / 待回访 / 今日到期 / 已完成 / 已逾期
- 客户姓名：模糊搜索

任务口径建议分两类：

- 待回访任务：未来或当前应执行，但尚未完成的任务。
- 超期任务：计划回访日期已早于统计日期，且仍未完成的任务。

**规则 1：产后回访**
产后回访的阶段依据应来自“生产日期”和“统计日期”的差值：

```text
产后天数 = 统计日期 - 生产日期
```

待回访任务统计：

- 只统计回访类型 = 产后回访。
- 只统计未完成任务。
- 按产后阶段聚合：
  - 15-30天
  - 30-45天
  - 45-60天
  - 60-75天
  - 75-90天
  - 90-105天
  - 105-120天
  - 120-135天
  - 135-150天
  - 150-165天
  - 165-180天
- 阶段边界建议采用左闭右开：
  - `15 <= 产后天数 < 30`
  - `30 <= 产后天数 < 45`
  - 依次类推。
- 表格按“负责顾问 + 阶段”统计人数。
- 一个产妇在同一统计日原则上只落入一个当前阶段。
- 点击数字时，进入该顾问、该阶段的产后回访任务明细。

产后超期分析：

- 只统计回访类型 = 产后回访。
- 只统计未完成且 `计划回访日期 < 统计日期` 的任务。
- 超期未回访产妇总数：符合超期条件的产妇数，建议按客户/产妇去重。
- 按顾问维度统计：每个负责顾问名下的超期未回访产妇数。
- 按阶段维度统计：每个产后阶段下的超期未回访产妇数。
- 点击顾问维度数字：查看该顾问下所有产后超期任务。
- 点击阶段维度数字：查看该阶段下所有产后超期任务。

**规则 2：服务回访**
服务回访的阶段依据应来自订单服务节点，不来自生产日期。

待回访任务统计：

- 只统计回访类型 = 服务回访。
- 只统计未完成任务。
- 当前页面已有两个服务阶段：
  - 上户5-7天
  - 下户3天
- 阶段生成建议：
  - 上户5-7天：根据订单上户日期生成，服务开始后第 5 到第 7 天需要回访。
  - 下户3天：根据订单下户日期生成，下户后第 3 天需要回访。
- 表格按“负责顾问 + 服务阶段”统计客户数。
- 点击数字时，进入该顾问、该阶段的服务回访任务明细。

服务超期分析：

- 只统计回访类型 = 服务回访。
- 只统计未完成且 `计划回访日期 < 统计日期` 的任务。
- 超期未回访客户总数：符合超期条件的客户数，建议按客户/订单维度去重，具体要看业务是否允许同一客户多订单。
- 按顾问维度统计：每个负责顾问名下的超期未回访客户数。
- 按阶段维度统计：
  - 上户5-7天
  - 下户3天
- 点击顾问维度数字：查看该顾问下所有服务超期任务。
- 点击阶段维度数字：查看该阶段下所有服务超期任务。

**需要确认的关键口径**
1. “待回访任务”是否包含“今日到期”？
我建议包含。即：`计划回访日期 >= 统计日期` 且未完成，其中今天就是今日到期。

2. “超期”是否从计划日期第二天开始？
我建议是：`计划回访日期 < 统计日期` 才算超期，`计划回访日期 = 统计日期` 是今日到期，不算超期。

3. 统计人数按“任务数”还是“客户数/产妇数”？
页面文案是“产妇数量 / 客户数量”，我建议统计时按人去重；明细里可以展示具体任务。

4. 服务回访如果同一客户有多个订单，按客户去重还是订单去重？
后端要确认。如果销售订单场景更强，我倾向按“订单 + 客户”作为唯一业务对象，避免不同服务订单被合并掉。
